## Why

The repository's documentation surface has grown into four written systems and five declared-but-unwritten ones, with no single entry point, no glossary, and no layer between seven long-form essays (1,927 lines) and sixteen normative specs (16,496 lines). A reader who wants to know what a mount point *is* has a choice between an essay that does not mention it and a thousand-line spec that presumes it. This change makes the repository an Obsidian vault whose spine is `docs/`, so that the same files serve human navigation and agent retrieval, and so that intent, decisions, specs and tasks are linked rather than merely co-located.

Two defects force it now rather than later. **The decision register has collided:** `docs/05-decision-log.md` and `design.md` both number decisions `D1`–`Dn` and disagree — `D4` is "version skew is governing" in one and "Runtime: Elixir + Go" in the other, `D7` is "frame-shaped" versus "timeout taxonomy", `D9` is "Runtime (reversed)" versus "domain ownership verification". This is already producing a wrong citation: `tasks.md:3` justifies the single-repository directory shape with "D2 and D4", which is only coherent if `D2` is read from `docs/05` and `D4` from `design.md`. **And every `file:line` citation in `docs/` is unverifiable:** 139 of them across 61 distinct files point into `reference/`, which is a one-line `.gitignore` entry with no repository URL and no fetch instructions anywhere, so the falsifiability rule that governs the whole doc system (`docs/method/documentation-rules.md#documentation`) is currently enforceable by no one but the author. Both defects get worse once 709 tasks begin citing paths and decision numbers.

## What Changes

- **The repository becomes the Obsidian vault.** Vault root is the repo root; `docs/` is the content spine; `openspec/` files are already notes in that vault and are linked into rather than duplicated. `.obsidian/` is partially committed (`app.json`, `core-plugins.json`); `workspace.json` and caches are ignored.
- **Relations are relative markdown links, not wikilinks.** One syntax that renders on GitHub, resolves for an agent without a search, feeds Obsidian's backlink pane and graph view, and is checkable by the link gate. `[[wikilinks]]` and `![[transclusion]]` are prohibited in tracked files.
- **A missing middle layer is added**: one concept note per capability (sixteen, roughly forty lines each) that links to its spec and to the capabilities it depends on, converting the eighty inert backticked cross-references in the specs into a navigable dependency graph — without editing a normative spec file.
- **The seven numbered essays are reorganised topically** into `why/`, `how/`, `capabilities/`, `decisions/`, `code/`, `history/`, `method/`, with reading order moved from filename prefixes into an explicit `start-here.md`. The rename cost is bounded and enumerable: **thirty-nine occurrences across ten pre-existing files** — fifteen written as `docs/NN-*.md` in backticked prose that no link gate can see, and twenty-four as bare relative markdown links of the form `](02-architecture.md)` inside `docs/` itself, which the link gate does see. `docs/README.md` holds eleven of them.
- **`docs/README.md` is retired into the spine.** It is the current index and holds the five governing facts and the "read in this order" table, both of which `start-here.md` takes over; its remaining orientation content moves into `why/`. It is not a note that survives alongside `start-here.md` — two indexes are the drift this change exists to remove — and it is the file the original rename inventory omitted entirely.
- **BREAKING — one decision register, and per-change decisions are namespaced.** `design.md`'s numbering wins, because it is the stated authority and it is what the specs cite. The seven decisions recorded *only* in `docs/05-decision-log.md` (rebuild-from-scratch, one-repository, contract-first-with-conformance, version-skew-as-governing-constraint, the positioning, WebTransport-deferred, observability-before-the-hot-path) are folded into `design.md` as `D21`–`D27`. `D11`–`D15` are deliberately left permanently unassigned, and a collision table records what the superseded register called every number. `docs/05-decision-log.md` is then deleted. The unnamespaced `D<n>` sequence belongs to that register alone: a change's own design decisions carry a prefix naming the change, so a change cannot open a competing register. This change's own ten decisions are `RDV1`–`RDV10` — they were `D1`–`D10`, colliding one-for-one with `rebuild-plugboard`'s, which is the defect this bullet declares BREAKING reproduced in the act of fixing it.
- **Every gate's scope is declared.** Each root is named governed or exempt in one retrievable location, an exempt root records what owns its files instead, and each gate reports the roots it excluded. Classification covers the spine and the per-component roots; links and reachability additionally cover the planning directories; tool-owned directories are exempt outright. Without this, "note" meant every tracked markdown file in the repository, which silently placed the sixteen specs under the frontmatter obligation and left the first gate written to resolve the contradiction in its own configuration.
- **A code style guide is introduced** covering component boundaries and what each directory must not own, how to add a feature, how to fix a bug, per-language conventions for Elixir and Go, testing discipline, and review. Every rule names its enforcing gate or is explicitly marked as taste with no gate.
- **Testing discipline is held as rules, not as prose.** The test tiers, the fast-tier latency budget as a correctness control, the conformance suite's authority, and the four prohibitions on test shape — a helper that performs the transition it waits for, a test asserting defective behaviour, a security property weakened in test configuration, an uncertainty marker standing in for a failing assertion — each become a rule note with its own anchor and cited defect. Left as prose in a methodology note they would carry no gate, appear in no rule index, and fall outside the correspondence check, which under this change's own quarantine rule would retire four review blockers by relocating them.
- **Banned patterns become atomic notes with stable anchors**, and the citation runs both ways: a gate's failure message names its rule note, and a rule note names its gate. Neither side can be added without the other.
- **New content that does not exist today**: a glossary, positioning against ngrok / cloudflared / frp / Tailscale Funnel / Caddy, a consolidated threat model, a failure taxonomy, an operator's view, a tenant's view, success criteria, research provenance, and instructions for obtaining `reference/` so the 139 citations become checkable.
- **REMOVED — `docs/agents/`.** All three files configure tooling that is not installed in this repository (`/wayfinder`, `/domain-modeling`, `/grill-with-docs`, a triage-label workflow), and `domain.md` additionally mandates a `CONTEXT.md` + `docs/adr/` decision system that competes with `D1`–`D20`. Its glossary role moves to the vault glossary; its decision role is already owned.
- **`CLAUDE.md` becomes a router.** It is 4,865 bytes against the 4 KB ceiling its own plan sets (`tasks.md` 1.3); roughly a kilobyte of it describes a graphify index that does not exist. It is rewritten to point into the vault, and `AGENTS.md` is created as its counterpart.

### Non-goals

- **The sixteen specs are not edited, and that is now asserted rather than promised.** Their paths form a declared out-of-scope set whose diff a gate requires to be empty across this change, because the instrument used to edit their sibling artifacts — `/opsx:update`, invoked seven times here — reconciles neighbouring artifacts in any direction over glob-expanded spec paths, and forbids only creating them, not revising them. Linking them directly stays deferred; the capability notes carry the graph from the vault side. Frontmatter on them was separately established to be tolerated by `openspec validate --strict`, and they are still excluded from the classification obligation on ownership grounds — an external tool owns their format.
- **`docs/06-carry-forward.md` is not atomised.** It stays one note with stable per-item anchors; an item is split out the first time a task cites it individually. Sixty files nothing links to yet is not navigation.
- **Dataview, Bases, Canvas and Excalidraw are not adopted.** Plugin-dependent views cannot be rendered by GitHub, executed by an agent, or diffed. Generated index notes serve the same purpose and are checked in.
- **No product behaviour changes**, and no directory from `tasks.md` 1.1 is created here.

## Capabilities

### New Capabilities

- `docs/knowledge-base`: the vault as a checked artifact — its root and spine, the declared governed and exempt roots that give every obligation a stated scope, the classification frontmatter, the link discipline and its gate, the authority precedence that keeps a note from stating behaviour a spec owns, the entry points and their size ceiling, the single decision register and the namespacing that stops a change opening a second one, the byte-unchanged assertion over any artifact declared out of scope, the two authoring channels, and the four currency properties that make "reflects the current state" verifiable in both directions rather than promised.
- `docs/code-standards`: the code guide as a cited artifact — a single canonical statement of each component's boundary, the rule-to-gate correspondence in both directions so a gate without a rule note and a rule note without a gate are both failures, the quarantine that keeps unenforced taste from being mistaken for a requirement, the task-shaped entry points for adding a feature and fixing a bug, and the testing obligations held in that same rule shape so the four prohibitions on test shape stay citable as blocking objections.

### Modified Capabilities

None. `openspec/specs/` is empty; `rebuild-plugboard` is in flight at 0 of 709 tasks and its requirements are unchanged by this change. Four of its tasks (1.1, 1.3, 1.4, 1.10) cite doc paths this change moves and are updated by it.

## Impact

- **Moved or deleted**: all seven `docs/NN-*.md` files, `docs/README.md`, all three `docs/agents/` files, `CLAUDE.md`. Thirty-nine references across ten pre-existing files are repointed — fifteen `docs/NN-*.md` paths in `CLAUDE.md`, `docs/07-methodology.md`, `rebuild-plugboard`'s `design.md` and its `tasks.md`, plus twenty-four bare relative links inside `docs/` itself, eleven of them in `docs/README.md`.
- **`rebuild-plugboard`**: `design.md` gains `D21`–`D27` and the collision table; tasks 1.1, 1.3, 1.4 and 1.10 are rewritten against the new paths and the new gates. Applied with `/opsx:update`, not by hand.
- **New CI gates — roughly thirty distinct checks across about a dozen families**, not the six this bullet first listed: declared note roots and their exclusions, link resolution and anchor resolution across tracked markdown, a wikilink and transclusion prohibition, frontmatter validity and spine-authority, note reachability from a declared entry point, generated-index drift, spine-versus-specification duplication, the single register and retired identifiers, the out-of-scope byte-unchanged assertion, citation and obtainability, capability-dependency correspondence, component boundaries, the bidirectional rule-to-gate citation check, the ungated-rule quarantine, per-language coverage, review single-sourcing, entry-file ceilings and absent-artifact refusal, four currency checks, the two-channel authoring keying, and the meta-check over all of them. Each gate is demonstrated against a deliberately broken input, per `docs/07-methodology.md`, and the aggregating target enumerates every gate it ran so the inventory is a build output rather than a prose list that can drift.
- **Authoring-time enforcement takes two channels.** `openspec/config.yaml`'s `context:`, `rules:` and `operations:` blocks are entirely commented out today, so nothing constrains an agent authoring a spec or a task, and nothing guides the apply and archive loops that will touch this vault across 709 tasks. All three are populated. But that file cannot be the whole answer: its `rules:` block is keyed per openspec artifact, so it cannot express an obligation on a note. A second channel — a hook, or a conventions note the entry files link first — reaches note authors, and both are generated from the same convention source so they cannot diverge.
- **Tooling**: Obsidian becomes a supported (not required) reader; a link checker and a small index generator become development dependencies. No runtime dependency changes.
- **Sequencing**: this change lands before `tasks.md` 1.1, so the directory shape and its READMEs are created against a doc structure that already exists.
